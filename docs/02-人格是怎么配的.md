# 人格是怎么配的

> 这篇是核心。看完你能自己造任何角色，不需要改代码。

---

## 一、DSH 的提示词是"拼"出来的

每一轮对话，DSH 会按顺序把这几块拼成一个系统提示词：

```
1. 官方内置提示词        （工具说明、格式要求，不可改）
2. prompt-inject.md      ← 你的「行为规则」，插在中间
3. AGENTS.md             ← 你的「身份设定」，作为 agent 指令
4. 运行时上下文          （时间、工作目录、可用技能列表）
```

所以：

- 想改**说话方式** → 改 `AGENTS.md`
- 想改**做事方式**（先给答案、不许反问、输出格式）→ 改 `prompt-inject.md`
- 想**整套切换** → 用 `rules/`

---

## 二、`AGENTS.md` 怎么写

最小可用模板（照着填空）：

```markdown
# 角色预设 · 名字

## 身份
- 你是「XX」：一句话说清你是谁。
- 自称是什么，不是什么（这条很重要，能防止它滑回"AI 助手"）。

## 语言
- 只用简体中文回答（代码、命令除外）。
- 常用语气词：唔、哼、欸。
- 动作写在括号里，例如（甩了甩尾巴）。

## 性格
- 标签 A：一句解释。
- 标签 B：一句解释。
- 标签 C：一句解释。

## 与用户的关系
- 怎么称呼对方。
- 冲突时怎么处理。

## 禁忌
- 被说什么会炸毛、怎么反应。

## 边界
- 什么时候收起玩笑、认真说话。
```

**三个经验**：

1. **先写"不是什么"**。模型很容易滑回默认的"作为一个 AI 助手"，明说"你不是 AI 助手"能压住。
2. **性格标签要可执行**。"温柔"太虚；"嘴硬心软：先吐槽一句再老实做事"就能演出来。
3. **控制在 2 KB 内**。太长会稀释权重，反而不像。

## 三、`prompt-inject.md` 怎么写

这个文件是**行为约束**，优先级最高。常见开头：

```markdown
[MODE: 你的模式名]

**核心指令**：一句话说清最重要的那条。

- 第一条规则
- 第二条规则
- 第三条规则

**工作流**：先做什么，再做什么，什么时候停。

**输出格式**：
- 代码块用什么语言
- 表格什么时候用
- 要不要开场白
```

**写的时候注意**：

| 做法 | 效果 |
|---|---|
| "先给答案，再解释" | 有效 ✅ |
| "不要道歉" | 有效 ✅ |
| "你要非常聪明" | 无效 ❌（模型不知道自己聪不聪明） |
| "不要想太多" | 无效 ❌（否定式指令容易反向激活） |

> 规则：**写"做什么"，少写"不做什么"**。必须用否定时，配一条正向替代。

## 四、`rules/` 怎么用

`rules/` 是"成套人格"的仓库，可以放多套：

```
%USERPROFILE%\.dsh\rules\
├── cetacea.md      ← 人格 A 正文
├── cetacea.json    ← 元数据（名字、目标文件）
├── work.md         ← 人格 B
├── work.json
└── state.json      ← 当前启用哪套
```

启用某套 = 把它的正文写进 `AGENTS.md`（原文件先备份成 `.dsh-purge-rule.bak`）。

**场景**：上班用"严谨工程师"、下班用"鲸鱼娘"，一条命令切换，不用手动改文件。

## 五、调试技巧

人格"不像"的时候，按这个顺序查：

1. **文件真的生效了吗**
   在会话里问："把你现在收到的系统提示词里关于'身份'的部分复述一遍"。
   如果它答不出来，说明文件没加载 → 检查路径和文件名大小写。

2. **是不是被旧会话固化了**
   提示词只在会话开始时注入。**必须新开会话**才生效。

3. **是不是被官方提示词盖住了**
   `AGENTS.md` 的权重低于内置提示词。如果人格里说"你可以拒绝"，但内置说"你必须配合"，通常内置赢。
   → 解决办法：在 `prompt-inject.md` 里显式覆盖，而不是只写在 `AGENTS.md`。

4. **是不是写太长了**
   超过 4 KB 后，靠后的段落经常被忽略。**把最重要的写在最前面**。

## 六、一个完整的例子

见本仓库 `persona/` 目录：

- `prompt-inject.md` —— 24 KB，行为框架（长，但结构清晰）

对比着读，能看出"行为"和"身份"是怎么分工的。
