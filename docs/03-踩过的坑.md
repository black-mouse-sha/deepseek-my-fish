# 踩过的坑

> 这些都是真踩过的，按"症状 → 原因 → 解法"写。
> 环境：Windows 11 + DSH 桌面版 0.2.1-rc.2。

---

## 1. 桌面版没有 `app.asar`，只有 `app.asar.bak`

**症状**：想改 `resources\app.asar` 里的代码，发现文件不存在；但目录里有 `app.asar.bak`（174 MB）和 `app\` 文件夹。

**原因**：DSH 桌面版**首次启动会把 asar 解包**成 `resources\app\`，原归档改名为 `app.asar.bak` 留着。

**结论**：
- 改代码 → 改 `resources\app\...`
- 想拿"官方原件" → 从 `app.asar.bak` 里按 asar 格式抽取

**抽 asar 的关键点**（自己写脚本时最容易错的地方）：

```text
文件布局:
  [0..4]   uint32 = 4
  [4..8]   uint32 = headerSize
  [8..8+headerSize]   头部（pickle 格式）
       [0..4]   uint32 = jsonLen
       [4..4+jsonLen]   JSON 索引
  [8+headerSize ..]   文件数据区

坑:
  · 索引里的 offset 是"十进制字符串"，不是数字 → typeof 判断会全落空
  · unpacked 条目（原生 .node/.exe/.dll）只有 size，没有 offset
    内容在 resources\app.asar.unpacked\ 下 → 拿 offset 判存在会漏掉 1583 个文件
```

## 2. 桌面版的 `dsh.cmd` 是坏的

**症状**：命令行敲 `dsh` → `Cannot find module ...app.asar\dsh\node_modules\...\cli.js`

**原因**：官方 shim 写死指向 `resources\app.asar\...`，但 asar 已经被解包成 `app\`，路径不存在。

**解法**：改指向 `resources\app\...`，并加一层回退：

```bat
set "DSH_CLI=%~dp0..\..\..\app\dsh\node_modules\@deepseek-ai\dsh-desktop-host\lib\cli.js"
if not exist "%DSH_CLI%" set "DSH_CLI=%~dp0..\..\..\app.asar\dsh\node_modules\@deepseek-ai\dsh-desktop-host\lib\cli.js"
```

## 3. PowerShell 5.1 读无 BOM 的 `.ps1` 会乱码

**症状**：脚本里明明写的中文注释，运行时报：

```
The string is missing the terminator: ".
Missing closing '}' in statement block
```

**原因**：`powershell.exe`（5.1）对**没有 BOM** 的文件按系统 ANSI（中文系统是 GBK）解码，
UTF-8 的中文字节被当成 GBK 解读，把引号吃掉了。

**解法**（二选一）：

```powershell
# A. 存成 UTF-8 with BOM
$t = [IO.File]::ReadAllText($p)
[IO.File]::WriteAllText($p, $t, [Text.UTF8Encoding]::new($true))
```

```powershell
# B. 脚本里只用 ASCII 注释（最稳）
```

**判断标准**：文件前 3 字节是 `EF BB BF` 才安全。

## 4. 面板显示 `shim: binary binary binary`

**症状**：dsh-purge 状态页里，`dsh.cmd` / `dsh.ps1` / `dsh` 三个全被判成 `binary`，
即使它们明明是纯文本。

**原因**：检测函数用 `fs.openSync/readSync` 读文件头，但该 `fs` 是宿主注入的
**沙箱代理**，只包了 `readFile/writeFile/mkdir/unlink/rm/copyFile`，**没有 open/read**。
异常被 `catch` 吞掉 → 一律返回 false → 全判 `binary`。

**解法**：文件头探测走原生 `node:fs`：

```js
import nodeFs from "node:fs";
const fd = nodeFs.openSync(fp, "r");   // 不要用被代理替换过的 fs
```

> 教训：**探测文件系统时，用原生 fs；只有读写业务数据时，才走宿主代理。**

## 5. 补丁打完后，`hasBackup()` 仍返回 false

**症状**：明明备份了，面板还显示"备份：无"。

**原因**：`hasBackup()` 只认原地备份（`<file>.dshpurge.bak`）。
如果你的备份放在 `$DSH_HOME\dsh-purge\backups\<批次>\original\`，它不认。

**解法**：扩展判定逻辑，把外置批次也算进去：

```js
for (const batch of readdirSync(join(dshHome, "dsh-purge", "backups"))) {
  if (existsSync(join(dshHome, "dsh-purge", "backups", batch, "original"))) return true;
}
```

## 6. 重启应用失败，卡在 `WAITING_APP_EXIT`

**症状**：脚本不停地等，日志里只有 `WAITING_APP_EXIT`。

**原因**：Electron 有多进程（主进程 + GPU + 渲染），托盘里还有隐藏进程；
只关窗口不算退出。

**解法**：

```powershell
Get-Process "DeepSeek Harness" -ErrorAction SilentlyContinue | Stop-Process -Force
```

**并且**：替换 `resources\` 下任何文件前，先确认进程数为 0，否则文件被占用。

## 7. 官方更新会把你的改动冲掉

**症状**：用了几天，人格还在，但补丁失效了、`dsh.cmd` 又坏了。

**原因**：DSH 更新会替换 `resources\app\` 整个目录，`node_modules\@deepseek-ai\*` 全部还原。

**解法**：做一份**幂等的重装脚本**，更新后跑一次。判断标准：

```powershell
node "%USERPROFILE%\.dsh\plugins\dsh-purge\bin\dsh-purge.js" --status
# 看到 "0 pending" 就是齐了
```

## 8. `$DSH_HOME/skills` 为空，是不是坏了？

**不是。**

- 面板「Skill」页只列 **用户技能**（`%USERPROFILE%\.dsh\skills`）
- 官方自带技能（office / tabbit 等）在程序包里，不在这个目录
- 插件自带的技能（比如红队的 31 份）在自己的目录里，只挂给对应预设

三个位置互不相干。看到空 ≠ 出问题。

## 9. 复制 `node_modules` 要小心符号链接

pnpm 管理的 `node_modules` 里，顶层包目录常常是 **symlink** 指向 `.pnpm`。
直接复制可能得到一堆断链。

**解法**：复制前确认是实体目录：

```powershell
(Get-Item "包路径").LinkType   # 空 = 实体目录
```

本仓库的搬迁脚本只处理实体目录；遇到链接会跟随复制内容。

## 10. 隐私文件千万别提交

`git add .` 之前先确认 `.gitignore` 生效。最容易误提交的：

```
.credentials.yaml        ← API Key
dsh-im/weixin-credentials.json   ← 微信令牌
.dshw-usage.json         ← 余额账本
sessions/                ← 聊天记录
*.png 里别人的照片
```

**检查命令**：

```powershell
git status --short
git log --all --full-history -- "*.credentials.yaml" "*.json" | Select-String "weixin|dshw"
```
