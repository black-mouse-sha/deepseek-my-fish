# 插件清单

> 本仓库**不分发插件源码**（版权属于各作者），只列清单。
> 装法：打开 DSH → 设置 → 插件市场 → 搜名字安装。

完整带版本号的清单见仓库根的 [`plugins.json`](../plugins.json)。

## 三、输出风格与工作纪律

不改模型能力，改它「怎么说话、怎么动手」。两个都靠插件自带的技能生效，装完即可在技能目录里看到。

| 插件 | 干什么 | 触发方式 |
|---|---|---|
| `dsh-ponytail` | 懒资深开发模式：每轮注入「能用的最少代码」规则集（YAGNI → 复用 → 标准库 → 原生 → 一行） | 自动生效；`/ponytail lite\|full\|ultra\|off` 调档，说「stop ponytail」退出 |
| `dsh-caveman` | 原始人输出风格：先给答案、去掉客套，技术事实与代码原样保留 | `/caveman`、`/ultracave`、`/megacave`（文言文）；含 commit / review / compress / stats |

两者都提供 6 个以上技能，会出现在技能目录里，模型可自行按场景调用。

> `dsh-ponytail` 的 peer 范围只声明到 DSH 0.1.x，在 0.2.1-rc.2 上要先把 `engines.dsh` 放宽并把 `settingsNamespace` 改成字符串命名空间，否则 bundle 会被兼容性检查跳过。仓库里记的是已打补丁的版本。

## 四、技能（不属于插件）

`%USERPROFILE%\.dsh\skills\` 下放的纯 `SKILL.md` 由宿主直接扫描，不需要任何插件。当前装了一套协作方法论（`solo-to-team-skills`）：派活与验收（`dispatch-accept-verify`）、交活前取证（`evidence-before-done`）、新手操作说明（`beginner-ops-writing`）、脱敏运营记录（`ops-case-notes`）。

技能不占工具位、不改提示词，只在被调用时载入正文，所以是「按需加载」而不是「常驻开关」。

---

## 五、注意

1. **插件自带的数据也在 `%USERPROFILE%\.dsh` 下**
   例如 `dsh-whale-widget` 的图片在它自己的 `assets\`，宠物状态在 `.dsh\pet.json`。
   换机时插件要重装，但**状态文件可以单独搬**（见仓库 README 的「搬家」部分）。

2. **插件版本不匹配可能起不来**
   DSH 大版本更新后，旧插件常常报错。装之前瞄一眼插件的 `package.json` 里的
   `peerDependencies` 或 README 的兼容说明。

3. **装太多会拖慢启动**
   每个插件都会往渲染进程塞资源。体积前 3 名（43 + 15 + 8 MB）加起来就 66 MB，
   只在需要时启用。

4. **别装来源不明的插件**
   插件跑在宿主进程里，权限等于你的账号权限。
